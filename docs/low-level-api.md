# Low-level API and ownership

Use one import: `package:ares_pdf/ares_pdf.dart`.

| Owner | Main responsibilities | Cleanup |
| --- | --- | --- |
| `AresPdfEngine` | Create/open/merge, conversion, crypto and capability checks | Await `close()` after its work. |
| `AresPdfDocument` | An independently owned document snapshot and its resources | Await `close()` for every returned document. |
| Reader document | Page/raster access with restricted operations | Close normally; a reader is not an editor lease. |

## Open, render and inspect

```dart
Future<int> inspectPdf(Uint8List pdfBytes) async {
  final engine = await AresPdfApi.connect();
  try {
    final doc = await engine.open(pdfBytes, mode: AresPdfOpenMode.reader);
    try {
      final count = await doc.pageCount();
      final size = await doc.pageSize(1);
      final png = await doc.renderPng(1, dpi: 96);
      // count, size and png are copied results owned by your app.
      return count;
    } finally {
      await doc.close();
    }
  } finally {
    await engine.close();
  }
}
```

Include `dart:typed_data` and the canonical import in this example. Raw `render`
returns BGRA raster data and dimensions; it is not encoded PNG. Keep DPI and page
size bounded in your UI to avoid excessive allocations. Do not assume PNG encoding
or every inspection operation remains available after trial expiry: only supported
basic reading/raster operations are retained.

## Immutable edits

`edit`, `select`, `fillForm`, `resetForm`, `flattenForm`, `attach` and `setMetadata`
return document snapshots that must be closed independently. Keep the input alive
until a dependent operation finishes. See the README's full `try/finally` pattern.
An unsuccessful edit must not silently replace your current document.

`merge` accepts open snapshots from the same engine. Cross-engine handles reject.
`select([3, 1])` copies unique **one-based** pages in the supplied order;
duplicate page selection rejects with `PDF_PAGE_RANGE`. `AresPdfAddPage.index`
is a zero-based insertion index. Check each DTO's coordinate policy in the reference.

## Source bytes versus generated bytes

`copySourceBytes()` copies exact native source bytes for supported original
documents. New/edited snapshots and protected readers reject where an exact-source
contract cannot be supplied. `exportBytes()` serializes authorized working bytes.
Neither should be used to infer cryptographic signature validity after edits.

## Resources and asynchronous work

Registered font and RGBA IDs belong to the native owner and its supported
descendants. Never persist IDs across engine recreation or copy them into another
viewer. Keep byte buffers alive until the awaited operation has captured them;
adapters snapshot input DTOs and native code rechecks ownership and permission.

Await commands and handle typed errors. Closing an owner is idempotent and
acknowledges the native cleanup barrier; recreating it does not reset licensing.
Stop issuing work when closed. Owners are not shared-memory objects to send between
Dart isolates. Transfer bytes and establish a new owner where needed.

## Capability checks

```dart
final caps = await engine.capabilities();
final nested = caps['core'];
final core = nested is Map ? nested : caps;
if (core['offlineOcspRevocation'] != true) {
  throw StateError('This binary does not support supplied OCSP evidence.');
}
```

Capabilities describe support, not a paid entitlement. Unsupported newer options
must fail explicitly rather than disappear. See [API reference](api-reference.md)
for every exported type and signature, and [troubleshooting](troubleshooting.md)
for meaningful error handling.
